# RestoreBench: 让 AI Agent 恢复潮流收敛

- **论文**: RestoreBench: Can AI Agents Restore Power Flow Convergence?
- **作者**: Riccardo Mansutti 等
- **来源**: arXiv:2609.00384 (cs.AI / eess.SY), 2026-08-31
- **代码**: https://github.com/Mansutti081/RestoreBench

---

## 1. 解决了什么问题

潮流计算不收敛是电力系统规划与运行中反复出现的痛点，诊断并恢复收敛通常需要工程师的经验判断和反复试验。该文第一次系统性地回答：LLM Agent 能不能自动化地"救回"不收敛的潮流算例？

## 2. 核心方法解读

你可以把它理解成给大模型出了一套"电力系统急诊医生"的考题。病人是 46 个不收敛的潮流算例（两个电网各 46 个），Agent 要像医生一样：先观察当前的潮流状态（observation），判断哪里出了问题，再决定动哪个"开关"——比如调整负荷、改发电机电压、投切电容/电抗器这些纠正动作（action space）。每做完一步就重新跑一次潮流，看收敛了没，收敛得越好分越高。关键是这套考题把环境（仿真器）、观察空间、动作空间、评分指标都定义清楚了，谁都能复现，成了社区一个统一的"考试标准"。

## 3. 算法/模型框架说明

```
不收敛算例 → 观察潮流状态 → LLM Agent 决策（单步纠正动作）
                ↑                        ↓
          仿真器反馈  ←—— 执行动作 & 重新计算潮流
                         ↓
                 收敛？→ 计分 / 换下一个算例
```

- 三种架构对比：chatbot（一问一答）、single agent（带工具和迭代规划的单智能体）、multi-agent（多智能体协作）
- 环境：两个电网，各 46 个需要一次或多次纠正动作的算例
- 评价：成功率、动作步数等指标，保证可复现

## 4. 关键创新点

1. 首个面向"潮流恢复"的 LLM Agent 基准（benchmark），填补了空白
2. 系统对比 chatbot / 单智能体 / 多智能体三种架构的能力边界
3. 定义了标准化的仿真环境 + 观察/动作空间 + 指标，可复现、可扩展

## 5. 与已有方法的区别

传统潮流收敛问题靠数值方法（如调整算法参数、同伦延拓法）或人工经验排查；LLM Agent 路线则是把"工程判断"这类隐性知识交给大模型做多步决策，属于 Agentic AI 新范式，与纯数值求解互补而非替代。

## 6. 为什么值得关注

- 直接对标"AI Agent + 电力系统"方向，是落地场景最具体的 Agent 基准之一
- 多步、带约束动作空间、依赖工程判断，正是当前 LLM Agent 最吃力也最有研究价值的设定
- 代码开源，可作为后续评测/改进 Agent 的起手框架

## 7. 待思考的问题

- 46 个算例规模偏小，扩展到更大电网（成百上千节点）后 Agent 还能否稳定决策？
- 纠正动作空间如何设计得更贴近真实调度（离散/连续混合、安全约束）？
- 能否把"物理约束"作为硬知识注入（用 solver 兜底），避免 Agent 给出不可行动作？
- 多智能体到底比单智能体好在哪？代价（token、延迟）是否值得？
