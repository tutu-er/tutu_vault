# ReAct: Synergizing Reasoning and Acting in Language Models

> **作者**: Shunyu Yao et al.  
> **会议**: ICLR 2023  
> **关键词**: reasoning, acting, agent, tool use, observation  
> **原文**: https://arxiv.org/abs/2210.03629

## 1. 解决了什么问题

CoT 让模型能写推理链，但它仍然关在文本内部。如果问题需要查资料、和环境交互、验证中间事实，仅靠内部知识会产生幻觉。传统行动型 agent 可以调用工具，却缺少显式推理轨迹，容易盲目行动。

ReAct 要解决的是：让语言模型在同一个轨迹中交替进行推理和行动，用推理决定下一步行动，用环境观察修正后续推理。

## 2. 核心方法

ReAct 的输出格式通常包含三类片段：

```text
Thought: 我现在需要判断什么
Action: 调用某个工具或执行某个动作
Observation: 环境返回的结果
```

模型不是一次性回答，而是在多轮循环中推进任务。Thought 负责计划和解释，Action 负责获取外部信息或改变环境，Observation 则把真实反馈写回上下文。

## 3. 原理解释

ReAct 的关键是把语言模型从“封闭生成器”变成“交互式策略”：

```text
context_t -> Thought_t -> Action_t -> Observation_t -> context_{t+1}
```

在这个循环里，模型的上下文既包含自身推理，也包含外部环境状态。相比纯 CoT，ReAct 可以用观察结果纠错；相比纯行动策略，ReAct 的中间思考提高了任务分解和可调试性。

## 4. 关键创新

1. **推理和行动交织**: 不是先完整推理再行动，而是边查边想、边做边修正。
2. **降低幻觉**: 需要事实时通过工具获取 observation，而不是完全依赖参数记忆。
3. **可解释轨迹**: 每一步为什么调用工具、观察如何影响后续决策，都能在文本轨迹中看到。
4. **少样本可用**: 通过 few-shot 示例即可诱导模型使用这种模式。

## 5. 与相关方法比较

| 方法 | 优点 | 局限 |
|---|---|---|
| CoT | 擅长内部推理 | 容易缺事实、无法行动 |
| Tool-only agent | 能调用环境 | 缺少显式计划和反思 |
| ReAct | 推理、行动、观察闭环 | 依赖工具接口和轨迹格式 |

## 6. 实验与结果

论文在知识问答、事实验证、交互式任务等场景中展示了优势。尤其在需要外部信息的任务上，ReAct 比纯 CoT 更可靠；在需要规划的环境任务中，它比只输出动作的策略更容易纠错。

ReAct 后来成为许多 LLM agent 框架的基本范式：计划、工具调用、观察、继续推理。

## 7. 为什么值得读

如果说 CoT 是让模型“写出思考”，ReAct 就是让模型“用思考驱动行动”。今天的工具调用、浏览器 agent、代码 agent、数据库 agent、自动研究助手，都能看到 ReAct 的影子。

它的思想非常朴素但影响巨大：LLM 不必一次性知道所有答案，只要能决定何时查、查什么、如何利用查到的信息，就能解决更复杂的问题。

## 8. 局限与思考

- Thought 文本可能泄露敏感推理或形成不稳定控制面。
- 工具返回错误时，模型可能过度信任 observation。
- 多步循环会带来成本、延迟和状态管理问题。
- 复杂任务需要更强的记忆、计划和错误恢复机制。
