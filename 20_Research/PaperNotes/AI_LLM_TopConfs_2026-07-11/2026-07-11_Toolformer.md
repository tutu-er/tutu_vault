# Toolformer: Language Models Can Teach Themselves to Use Tools

> **作者**: Timo Schick et al.  
> **会议**: NeurIPS 2023  
> **关键词**: tool use, APIs, self-supervised learning, language models  
> **原文**: https://arxiv.org/abs/2302.04761

## 1. 解决了什么问题

语言模型擅长语言生成，却不擅长精确计算、实时事实查询、日期处理、翻译调用等外部功能。人工写工具调用数据成本高，而且很难覆盖所有调用时机。

Toolformer 要解决的是：能否只给少量工具调用示范，让模型在大规模普通文本中自动标注“何时调用工具、调用什么、参数是什么、结果如何写回文本”，然后自监督地学会使用 API？

## 2. 核心方法

Toolformer 的训练流程是：

1. 为每个工具提供少量人工示范，教会模型工具调用格式。
2. 在普通文本中采样可能插入工具调用的位置。
3. 让模型生成候选 API 调用。
4. 实际执行 API，得到返回结果。
5. 比较插入工具结果前后的语言建模损失，只保留能降低损失的调用。
6. 用筛选出的工具调用文本继续微调语言模型。

关键思想是：如果某个工具结果能让模型更好预测后续文本，这个调用就是有用监督信号。

## 3. 原理解释

Toolformer 把工具使用转化为语言建模数据增强问题。一个训练样本从：

```text
The result of 123 * 45 is ...
```

变成：

```text
The result of [Calculator(123 * 45) -> 5535] is 5535 ...
```

模型学习的不只是答案，而是工具调用的四个决策：

- 是否调用；
- 调用哪个 API；
- 传什么参数；
- 如何把返回结果融入后续生成。

## 4. 与 ReAct 的区别

| 维度 | ReAct | Toolformer |
|---|---|---|
| 学习方式 | prompt 诱导为主 | 自监督微调 |
| 工具调用 | 任务轨迹中显式交互 | 训练进模型行为 |
| 数据来源 | 少量示例 / 环境交互 | 大规模普通文本自动标注 |
| 目标 | agent 推理行动闭环 | 让 LM 内化 API 使用能力 |

ReAct 更像运行时框架，Toolformer 更像训练数据生成和模型能力注入方法。

## 5. 实验与结果

论文把计算器、问答系统、搜索引擎、翻译系统、日历等工具接入语言模型。结果显示，模型在若干 zero-shot 下游任务上明显提升，同时基本不损害原始语言建模能力。

这说明工具使用不一定需要大量人工轨迹，也可以通过“工具结果是否降低困惑度”来自动筛选训练信号。

## 6. 为什么值得读

Toolformer 是工具增强 LLM 的代表性论文。它把外部工具从 prompt 工程变成可训练行为，回答了一个重要问题：模型是否能自己发现工具调用的价值？

对今天的 agent 研究，它启发了自动工具标注、API 调用数据合成、函数调用微调和执行反馈训练等方向。

## 7. 局限与思考

- 工具调用筛选依赖语言建模损失，未必等同于任务成功。
- API 格式和工具集合固定，泛化到新工具仍需要额外机制。
- 对需要多步计划的任务，单次工具插入不够。
- 工具结果错误或过时会污染训练信号。
