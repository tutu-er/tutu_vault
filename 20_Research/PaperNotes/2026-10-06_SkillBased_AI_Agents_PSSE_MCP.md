## 1. 解决了什么问题

输电规划里大量时间是"操作仿真软件"而不是"做判断"——搭潮流、跑动态仿真、提结果、校模型。本文要解决的是：**能不能用基于技能（skill）的 Agent 框架，把 PSSE 这类工业级仿真工具包进 MCP，让 LLM Agent 自动完成常规仿真与结果提取，把人解放出来做场景设计与解释**。

## 2. 核心方法解读（师兄视角）

思路是"把工程软件变成 Agent 能调用的工具"。他们写了一个自定义 MCP Server，把西门子 PSSE 的潮流分析、动态仿真、结果提取、模型校核这些功能暴露成标准化的 MCP 工具；再往上叠"技能（skill）"和子 Agent。这样 LLM 不用懂 PSSE 的命令细节，只要会说"跑这个算例、把这个母线电压提出来"，框架就会去调用对应技能。文章比较了两条实现路径——基于 OpenAI Agents SDK 的编程式、和基于 Claude Code CLI 的命令行式——两条都能跑通代表性算例，用公开数据验证了"Agent 能大幅加速动态仿真流程"。

## 3. 算法/模型框架说明

- **MCP Server**：封装 PSSE 的潮流/动态仿真/结果提取/模型校核函数为工具。
- **技能 + 子 Agent**：可复用 skill 库，subagent 分工，配合数据仓库连接与本地 shell/Python 执行。
- **两条路径**：OpenAI Agents SDK（编程式）与 Claude Code CLI（命令行式）。
- **评测维度**：任务完成率、输出准确性、需要人类专家干预的次数（公开数据集）。

## 4. 关键创新点

1. **把工业级仿真平台（PSSE）标准化为 MCP 工具**，是"Agent 进入真实工程软件"的落地样板。
2. **技能（skill）+ 子 Agent 的模块化组织**，把隐性工程流程沉淀成可复用资产。
3. **双路径对比评测**，量化了 agentic 系统在输电规划中的实际加速效果与人工干预成本。

## 5. 与已有方法的区别

很多"LLM 用于电力系统"的工作停留在让模型读文本、写潮流脚本或做问答，工具调用是零散、非标准的。本文的差别在于：**用 MCP 协议把企业级仿真软件做成一套标准化工具接口**，并真正在工业级平台上跑通动态仿真流程，评测还明确统计了"需要几次人工干预"——这是从"能用"走向"可靠工程化"的关键一步。

## 6. 为什么值得关注

如果要做"电力系统工程 AI Agent"，这篇文章给了一条可复制的工程路径：MCP 封装工具 + 技能库 + 子 Agent，而且已经对齐到工业软件（PSSE）与真实算例。它也从侧面说明"Agent 的瓶颈不在模型，而在工具接口与技能沉淀"，这跟我们把研究做成可用系统的思路高度一致。

## 7. 待思考的问题

- 准确性与人工干预的边界如何设定？哪些步骤必须保留 human-in-the-loop 才算安全可交付？
- MCP 封装的 PSSE 工具是否开源可复用？能否平移到 PSS®E 之外的平台（如 PSCAD、DIgSILENT、Grid2Op）？
- "技能"如何沉淀与版本管理？技能库能否跨算例、跨团队复用，还是每换一个场景就要重写？
- 动态仿真的"正确性"如何自动校验（不只是"跑完"，而是"跑对"）？
