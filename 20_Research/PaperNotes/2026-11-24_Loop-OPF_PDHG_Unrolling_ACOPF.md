## 1. 解决了什么问题

「学习求解 OPF」这几年很火，但大多数方法都存在两个硬伤：一是预测出来的解不保证最优、甚至不保证潮流可行（约束可能被违反）；二是网络一旦换拓扑（比如断一条线路、停一台机组），训练好的网络基本就废了，必须重训。Loop-OPF 就是要同时解决「最优性+可行性保证」和「推理时拓扑自适应」这两个问题。

## 2. 核心方法解读（师兄讲解版）

先回忆一下传统做法：训练一个神经网络，输入负荷需求，直接吐出一个调度解，然后拿它去跟求解器比误差。问题在于，神经网络是个"黑盒函数拟合器"，它不知道什么是最优潮流，也不知道约束在哪，所以吐出来的解经常违反约束、也谈不上最优。

Loop-OPF 的思路很聪明——**它不拟合"解"，而是拟合"求解器"**。

具体来说：DC-OPF 本质上是一个凸优化问题，可以用 PDHG（primal-dual hybrid gradient，原始对偶混合梯度）这类一阶算法迭代求解。PDHG 的每一步迭代都是一个固定的数学运算：先更新原始变量，再更新对偶变量。Loop-OPF 把 PDHG 的**每一次迭代展开成神经网络的一层**，于是这个网络的每一层都严格对应求解器的一步，层层叠起来就是一个"迭代到收敛"的求解器。

这样做的直接好处：因为每一层就是 PDHG 的迭代（数学上是凸的、满足正则条件），所以**网络跑到底（不动点）输出的解，天然就是最优且可行的**——不再是黑盒拟合，而是"带着收敛保证的求解器"。

那"学习"体现在哪？体现在 PDHG 里有几个步长/参数，这些参数在传统算法里是靠经验调的，Loop-OPF 用**自监督**的方式去学它们，让算法收敛得更快——注意，**完全不需要任何 OPF 解标签**，因为目标就是"让不动点满足 KKT 条件"，这是可以无监督定义的。

关于拓扑自适应：PDHG 迭代里，网络拓扑（导纳矩阵）是作为**输入**喂进每一层的。所以换拓扑的时候，同一个网络直接把新拓扑当输入就行，**不用重训**。

最后是工程细节：层数多了内存会爆炸，所以用 DEQ（deep equilibrium，深度平衡模型）来训练——不显式存中间层，只解不动点方程，内存开销与层数无关。

## 3. 算法/模型框架说明

```
输入: 负荷需求 + 电网拓扑(导纳矩阵,每层都输入)
              ↓
┌─────────────────────────────────────┐
│  Loop-OPF (把 PDHG 迭代展开成层)     │
│  Layer 1: 原始变量更新 (primal)      │
│  Layer 2: 对偶变量更新 (dual)        │
│  Layer 3: 原始更新 …                 │
│  … 循环到不动点 (fixed point)        │
│  学习目标: 自监督学习 PDHG 步长参数   │
│  (无需 OPF 标签)                     │
└─────────────────────────────────────┘
              ↓
   不动点输出 = 最优且可行的 DC-OPF 解
```

- **骨架**：PDHG 迭代的展开（unrolling），网络结构由算法本身决定
- **训练**：DEQ 框架，自监督（无标签），目标是让不动点满足最优性条件
- **保证**：凸性+正则条件下，不动点输出最优可行
- **拓扑自适应**：导纳矩阵逐层作为输入，换拓扑不重训
- **验证规模**：IEEE 300 节点 + PEGASE 1354/2869/9241 节点，覆盖大系统

## 4. 关键创新点

1. **求解器知情的架构**：不是"神经网络拟合 OPF 解"，而是"神经网络实现 OPF 求解器"，把保证内建到结构里
2. **可行性+最优性保证**：这是 learning-for-OPF 里极少能做到的，绝大多数方法只能"近似"
3. **自监督、无标签训练**：不需要用求解器预先生成海量标签，省掉了一大块数据成本
4. **推理时拓扑自适应**：断线/停机等 N-1 场景直接适配，不需要重训
5. **DEQ 解决内存问题**：层数再多，内存开销恒定

## 5. 与已有方法的区别

| 维度 | 传统 learning-for-OPF | Loop-OPF |
|------|----------------------|----------|
| 学习对象 | 直接学"解"（输入→调度） | 学"求解器"（PDHG 迭代） |
| 最优性/可行性 | 不保证 | 结构上保证 |
| 标签需求 | 需要大量 OPF 解标签 | 自监督，无标签 |
| 拓扑变化 | 需重训 | 逐层输入拓扑，直接适配 |
| 训练内存 | 随层数线性增长 | DEQ，恒定 |

## 6. 为什么值得关注

这是"学习加速优化（learning to optimize）"在 OPF 上目前我看到最严谨的一个工作。它抓住了本质——**与其让网络学结果，不如让网络学算法**。保证可行性这一点对电力系统尤其重要，因为一个违反潮流约束的调度解在实际中毫无意义。而且自监督+无标签意味着落地成本低，代码也开源了，可以直接拿来做基线或在其上改。

## 7. 待思考的问题

- 论文在 **DC-OPF**（凸）上给出保证，**AC-OPF 是非凸的**，不动点的最优性保证还成立吗？作者有没有扩展到 AC 的路线图？
- PDHG 收敛速度本身不算快，学出来的步长能在多大程度上加速？相比直接用成熟的 IPM（内点法）求解器，实际 wall-clock 时间优势有多大？
- 对偶变量/乘子的解释性如何？能否顺带输出节点边际电价（LMP），这对我做电力市场方向很有用。
- 超大规模（几万节点）上的数值稳定性、收敛判定阈值怎么选？
- 能否把「自监督学习求解器参数」的思路迁移到 UC（机组组合，混合整数）或其他带整数变量的问题上？
