# PowerAtlas: Towards Electricity-Computing Co-Scheduling for Power Systems

- **论文信息**: Kaiwen Jiang, Siya Xu, Ziyue Zhu, Chao Yang, Anh Tuan Luu, Haoran Luo，arXiv:2607.26710，2026-07
- **链接**: https://arxiv.org/abs/2607.26710 ｜ 代码: https://github.com/JAVA-Jiang/PowerAtlas
- **领域**: LLM-Agent / 电力-算力协同调度 / 机组组合（UC）/ 强化学习
- **备注**: 北邮 + 国网辽宁 + 南洋理工合作，含真实部署（deployment）

## 1. 解决了什么问题

AI 负载让数据中心变成大规模、易波动、但可时空转移的电网负荷。如果让通用大模型直接生成"机组调度 + 算力任务放置"的联合决策，结果经常违反潮流约束、导致弃荷（unserved load）。本文要解决的核心矛盾是：**既要满足电网运行规则（物理可行），又要满足算力任务的 SLA（服务等级），还要便宜**——三件事耦合在一起，单靠 LLM 的"语感"做不到物理可行。

## 2. 核心方法解读（师兄讲给你听）

师兄给你拆一下这个问题的本质：这其实是一个**"机组组合（UC）+ 算力调度"的联合优化**，两个领域通过"功率平衡"和"数据中心容量"耦合在一起。

- 电网这边：决定哪些发电机开、开到什么百分比，还有一个"平衡机（swing unit）"负责吃掉剩下的功率差，让节点功率平衡天然成立；
- 算力这边：把每个任务分配到 4 个数据中心之一（每个 11 个机架），决定是"放下（drop）还是托管"，以及开始时间；
- 耦合点：数据中心的功耗进入功率平衡，反过来算力任务受电网可用容量约束。

通用 LLM 直接输出这个联合决策，十有八九会翻车（违反线路潮流约束）。作者的做法是**"LLM 智能体 + 可行性对齐训练"**：

1. **冷启动（warm-start）**：先用已经解到最优的历史案例给智能体做示范/检索，把"好的答案长什么样"喂进去，而不是从零瞎猜；
2. **结构化上下文**：把输入拆成任务描述、知识增强（调度规程/标准）、输出格式三块，强制 LLM 输出可解析的结构化决策；
3. **确定性验证器**：对 LLM 生成的每个决策，用确定性的物理程序逐条核对电网违规和算力违规，量化"两个领域各违反了多少"；
4. **FA-GRPO（可行性感知的组相对策略优化）**：把"可行性 + 成本"写进奖励函数，用强化学习微调策略 πθ，让输出的决策 D 同时逼近最优解 D* 的可行性与经济性。

关键一句话：**用"确定性物理验证"把不可微的可行性变成可优化的奖励信号**，再用 GRPO 对齐策略。

## 3. 算法/模型框架说明

```
耦合规格 S = (S_T 任务描述, S_K 领域知识, S_F 输出格式)
        │
        ▼
   LLM Agent 策略 πθ(S) ──输出──> 联合决策 D = (发电机调度 D_G, 算力放置 D_C)
        │                                    │
        │                     ┌──────────────┴──────────────┐
        │                     ▼                              ▼
        │             确定性验证器                    确定性验证器
        │           (电网违规: 线路潮流)           (算力违规: SLA/容量)
        │                     └──────────────┬──────────────┘
        │                                    ▼
        └────────── FA-GRPO 奖励 = 可行性(两域违规) + 成本
                     （逼近 oracle 最优 D* 的可行性与经济性）
```

ECBench 基准构建（四阶段）：从电网文档、真实数据中心数据、LLM 辅助生成合成耦合场景 → 每个实例解到最优 → 物理合规验证 → 得到 2000 个带 oracle 最优解的实例。

## 4. 关键创新点

1. **提出 ECCS 任务**：把"发电机调度 + 算力任务放置"在统一电网安全约束与算力 SLA 约束下联合建模，通过功率平衡与数据中心容量耦合；
2. **FA-GRPO**：把两域的"确定性可行性验证"融入奖励设计，让 LLM 策略同时逼近最优的可行性与成本——这是把物理约束可微化/可训练化的关键；
3. **ECBench 基准**：2000 个带 oracle 最优解的实例，可复现、可对标，填补了"电力-算力协同调度"无基准的空白；
4. **真实部署验证**：与省级电网合作建实验网络，在真实数据中心数据上验证决策闭环，且代码开源。

## 5. 与已有方法的区别

| 方法 | 关键区别 |
|------|----------|
| 通用 LLM 直接生成调度 | 只做"文本生成"，无物理校验，常违反潮流约束 |
| 传统 UC 求解器（MILP） | 可行但算力任务放置与 SLA 是软约束，难以联合建模、无法利用自然语言上下文 |
| 纯 RL（端到端） | 需要仿真器交互、样本效率低，且难利用领域知识与历史案例 |
| LLM + 简单提示工程 | 只改提示不改权重，物理可行性仍靠"运气" |
| **PowerAtlas** | **LLM-Agent + 检索冷启动 + 确定性验证 + FA-GRPO 权重对齐**，四者闭环 |

## 6. 为什么值得关注

- **方向最对口**：AI（LLM）× 电力系统（UC/潮流约束）的直接交叉，且把"算力"作为可调度柔性资源引入电网；
- **方法论完整**：检索、验证、奖励对齐、基准、部署一整套闭环，不是"演示 demo"而是可复现系统；
- **可迁移性强**：FA-GRPO 的"物理可行性奖励对齐"思路，可迁移到 VPP 报价、市场竞价、DER 聚合等任何"LLM 决策 + 物理约束"的场景；
- **顶会潜力 + 真实落地**：有真实电网合作数据与在线部署实验。

## 7. 待思考的问题

1. FA-GRPO 的奖励是"验证器的 0/1 可行性 + 成本"，能否把验证器的梯度信息（如违规程度、灵敏度）进一步利用，而不是只当黑盒判分？
2. 这里的电网侧是简化的 DC/机组组合模型，能否接入 AC-OPF 级别的潮流约束？LLM 决策在更严格的物理下还稳得住吗？
3. 算力任务的 SLA 建模较粗（优先级/截止时间/丢弃惩罚），能否细化到训练 vs 推理、批处理 vs 流式的不同灵活性？
4. 与 VPP/DER 聚合的思路能否打通：把"数据中心"替换成"广义 DER 聚合体"，PowerAtlas 框架是否直接适用？
