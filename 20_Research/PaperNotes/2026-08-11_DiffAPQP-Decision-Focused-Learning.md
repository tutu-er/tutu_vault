# DiffAPQP: Structured Differentiable Optimization for Efficient Decision-focused Learning in Power Systems

- **论文信息**: arXiv:2608.04189, 2026年8月
- **链接**: https://arxiv.org/abs/2608.04189

---

## 1. 解决了什么问题

Decision-focused learning (DfL) 的核心思想是"预测不是为了预测本身，而是为了后续决策更好"——比如预测电价不是为了报得准，而是为了报完价能赚更多钱。但DfL在电力系统中很难落地，因为每次训练都要反复求解和微分大型优化问题（UC/OPF动辄几千个变量）。这篇工作提供了一个通用加速框架DiffAPQP，把DfL训练速度提升了3~6倍。

## 2. 核心方法解读

先理解为什么DfL这么慢。

传统"预测+优化"是两阶段：先训练预测模型（最小化预测误差），然后把预测结果喂给优化器求解。问题在于——**预测误差最小≠决策效果最好**。可能在电价$50时预测$51无所谓，但在$100时预测$99就亏大了。

DfL直接把决策损失（比如实际运行成本）反向传播到预测模型里训练。但梯度要穿过整个优化问题——这就涉及到对KKT条件求导，矩阵又大又稠密，算一次梯度可能比解一次OPF还慢。

DiffAPQP的加速手段非常工程化：

### 前向加速
- **自动规范化**：把CVXPY写的电力模型自动转成"微分友好"的标准QP形式
- **热启动+求解器数据更新**：利用训练中相邻迭代的相似性，不用每次从零开始求解

### 反向加速（真正的杀手锏）
- **核心洞察**：微分只需要**活跃约束**。那些不绑定的不等式约束，导数都是零
- 于是从全KKT系统（可能有几千维）中剔除不活跃约束，得到一个小得多的"约化系统"
- 对于只依赖最优值的损失函数，更进一步——用**包络定理（Envelope Theorem）**直接算梯度，完全不需要求解伴随KKT系统

这就像你去超市买东西，本来要在所有货架间走一遍（全KKT），现在你知道了：不买的东西直接跳过（剔除不活跃约束），而且如果只关心总价（最优值），拿小票看一眼就行（包络定理）——连走到收银台都不用。

## 3. 算法/模型框架

```
┌──────────────────────────────────────────────────┐
│                  DiffAPQP 框架                      │
├──────────────────────────────────────────────────┤
│                                                    │
│  训练循环:                                         │
│  ┌─────────┐    ┌──────────┐    ┌──────────────┐ │
│  │预测模型  │───▶│  QP求解   │───▶│ 决策损失▽    │ │
│  │(NN/GBDT) │    │(热启动)   │    │(包络定理梯度) │ │
│  └─────────┘    └──────────┘    └──────────────┘ │
│       ▲                              │            │
│       └──────── 反向传播 ◀───────────┘            │
│                                                    │
│  关键技术:                                         │
│  • 前向: CVXPY→标准QP规范化 + 热启动               │
│  • 反向: 活跃约束筛选 + 包络定理梯度               │
│  • 求解器: SCS / Clarabel (支持GPU加速)            │
└──────────────────────────────────────────────────┘
```

**实验配置与结果：**
- 在IEEE 118-bus系统上做24h经济调度+再调度（这是首个基于求解器的端到端DfL在118节点上的演示！）
- vs CvxpyLayers基准：
  - Closed-loop训练加速 **2.27x~3.58x**
  - Counterfactual训练加速 **3.62x~4.38x**
  - 最佳配置下：epoch时间从38.65min降到9.55min（3.91x），counterfactual从10.73min降到1.68min（6.39x）
  - 峰值内存降低约 **50%**
  - 运行成本与CvxpyLayers相当

## 4. 关键创新点

1. **首个求解器无关的DfL框架**：支持不同QP求解器后端（SCS/Clarabel），不像CvxpyLayers绑定特定求解器
2. **活跃约束约化 + 包络定理梯度**的组合拳：理论简洁但工程效果显著
3. **首个在118-bus 24h调度上端到端DfL的演示**：之前没人能在这么大系统上跑通
4. **开源Python包**：直接pip install可用

## 5. 与已有方法的区别

| 维度 | CvxpyLayers | 纯ML预测+优化 | DiffAPQP |
|------|-------------|-------------|----------|
| 训练目标 | 决策损失 | 预测损失 | 决策损失 |
| 梯度路径 | 全KKT微分 | 无（两阶段） | 约化KKT+包络定理 |
| 求解器 | 绑定特定 | 任意 | 灵活切换 |
| 大规模可行性 | 118节点很慢 | 可行但次优 | 118节点加速6x |
| 内存 | 高 | 低 | 降低50% |

## 6. 为什么值得关注

对于做电力系统优化的研究者来说，这个工具打开了"端到端学习"的大门。以前你可能用ML预测负荷/电价，然后扔进UC模型求解——虽然简单但效果不一定最优。现在DiffAPQP让你能把**整个优化模型嵌进训练过程**，让预测模型真正为"降低总运行成本"而训练。而且它的加速效果意味着在个人工作站上就能跑118-bus级别的DfL实验。

## 7. 待思考的问题

- 包络定理梯度只适用于"最优值"损失——如果你关心的是最优解向量（如具体调度方案）呢？
- 处理整数变量（UC的启停决策）时，QP框架是否适用？MILP的微分呢？
- 在带有随机性的场景（随机OPF、鲁棒UC）中，DfL的梯度传播路径是什么？
- 如果优化问题是non-convex的（如AC-OPF），框架还能工作吗？
