# AgentiGrid: 大模型智能体 + 高性能计算驱动的电网规划（AC-OPF）自动化

- **arXiv**: [2609.04544](https://arxiv.org/abs/2609.04544)
- **日期**: 2026-09-15
- **标签**: #LLM #Agent #ACOPF #HPC #Optimization #GridPlanning

---

## 1. 解决了什么问题

大规模电网规划需要反复跑「多场景潮流/最优潮流（OPF）研究」，而传输约束下的交流最优潮流（AC-OPF）是个非线性非凸难题，传统流程依赖专家不断手工调参、跑算例、读结果、再调，既慢又难规模化。这篇要解决的是：**能不能让一个大模型智能体（LLM Agent）自己闭环地完成「提假设 → 调用求解器 → 解读结果 → 决定下一步」这一整套规划流程。**

## 2. 核心方法解读（师兄讲解版）

你可以把它理解成一个「会自己动手做潮流实验的 AI 研究员」。

传统做法是：你（人）手动改几个参数 → 跑一次 OPF → 看收敛没、成本多少 → 再猜下一步改什么。循环几十次，很累。

AgentiGrid 的做法是让 LLM 当这个「研究员」：

1. **LLM 提方案**：根据当前目标和已有结果，提出要改哪些参数（比如调整某个发电机的出力上限、改某条线路的约束）。
2. **调 ExaGO 跑算例**：ExaGO 是一个高性能计算（HPC）工具包，能跑确定性、随机、安全约束多种 OPF。
3. **读结果**：LLM 解读算例输出（收敛与否、目标值、越限情况），判断好坏。
4. **决定下一步**：继续调参还是收工，全程自主。

关键设计有三点：

- **交互式中途 steering**：人可以中途介入，给 LLM 指示「换个方向」，不是黑盒一键到底。
- **目标类型感知的后期分析**：算完不是只报个数，而是根据你的目标类型（找可行解？降成本？）做针对性总结。
- **并发变体探索**：同一时刻并行尝试多个参数组合，加速搜索。

结果很漂亮：**传输约束 AC-OPF 能在 20 次迭代以内自主收敛，且近乎百分百可靠**。还有个 Streamlit 图形界面，实时看迭代进度，最后用自然语言出报告。

## 3. 算法/模型框架说明

```
用户目标（自然语言 / 配置）
       ↓
┌──────────────────────────────────────┐
│   LLM 智能体（Orchestrator）          │
│   - OpenAI / Anthropic / Ollama 后端 │
│   - 上下文 + 任务专用提示词           │
│   - 提出参数修改 → 解读结果 → 决策    │
└──────────────┬───────────────────────┘
               ↓ 调用分析
┌──────────────────────────────────────┐
│   ExaGO（HPC 分析工具包）             │
│   - 确定性 OPF                        │
│   - 随机 OPF                          │
│   - 安全约束 OPF（SCOPF）             │
└──────────────────────────────────────┘
               ↓
   结果 → LLM 解读 → 自然语言报告
   （Streamlit 前端实时可视化迭代进度）
```

核心组件：
- **多 LLM 后端**：OpenAI、Anthropic、Ollama、Ollama Cloud，可切换。
- **ExaGO**：Paciﬁc Northwest 系的 HPC 潮流/OPF 工具，支持确定性、随机、安全约束 OPF。
- **闭环决策循环**：`提议参数 → 调用 ExaGO → 解释 → 决定下一步`，直到收敛或达到停止条件。

## 4. 关键创新点

1. **LLM + HPC 的闭环整合**：不是让 LLM 直接「算」OPF（会错），而是让 LLM 当决策者、HPC 当算力，各司其职。
2. **交互式 steering + 并发变体探索**：保留人的介入点，同时并行搜索加速。
3. **多后端、可本地部署**（Ollama）：避免完全依赖闭源 API。
4. **在真实 HPC OPF 求解器上验证**，而非 toy benchmark；<20 次迭代收敛传输约束 AC-OPF。

## 5. 与已有方法的区别

| 维度 | 传统手工流程 | 已有 LLM+电力系统框架 | AgentiGrid |
|------|------------|---------------------|-----------|
| 求解方式 | 人反复调参 | LLM 编排工具链 | LLM 闭环 + HPC 求解 |
| OPF 类型 | 通常单一确定性 | 多为确定性潮流 | 确定/随机/安全约束 |
| 人机交互 | 全程人工 | 少或无 | 交互式中途 steering |
| 并行搜索 | 无 | 无 | 并发变体探索 |
| 后端 | — | 多为闭源 API | 多后端含本地 Ollama |

## 6. 为什么值得关注

- 它把 **LLM 的「智能调度」和 HPC 的「硬算力」** 这对组合落地到了电网规划最难的 AC-OPF 上，方向很对——LLM 负责决策/解释，数值计算交给专业求解器。
- 安全约束/随机 OPF 的接入意味着能往「不确定性 + 可靠性」方向扩展，这正是运行刚需。
- EnergyCon 2026 接收、多后端开源，容易复现和在其上做二次研究。

## 7. 待思考的问题

- **收敛保证**：20 次迭代收敛很漂亮，但有没有理论保证？遇到病态算例会怎样？
- **实时性**：LLM 推理 + HPC 调用的往返延时，能否支撑在线运行，还是只适用于离线规划？
- **幻觉安全**：LLM 解读结果时会不会误判收敛状态？有无 safety guard？
- **规模扩展**：从规划算例到更大规模的联合 UC+OPF、多时段问题，可扩展性如何？
- **与优化求解器的边界**：到底哪些决策该交给 LLM、哪些该留在求解器里，是个需要想清楚的设计问题。
