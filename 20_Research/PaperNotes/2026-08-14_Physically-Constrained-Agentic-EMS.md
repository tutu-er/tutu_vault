# Physically Constrained Agentic AI for Energy Scheduling（物理约束的智能体能源调度）

- **arXiv**: [2608.09029](https://arxiv.org/abs/2608.09029)
- **收录日期**: 2026-08-14
- **领域**: AI Agent / 家庭能源管理 / 混合整数调度
- **分类**: eess.SY（IEEE PES IM，5 页短文）
- **作者**: Dafang Zhao 等

---

## 1. 解决了什么问题（1-2句话）

Agentic AI 能听懂自然语言指令并调度家电/EV/暖通，但 LLM 生成"看起来合理、物理上不可行"的方案是老问题。本文要解决的是：**如何让一个 ReAct 智能体在自由生成调度方案的同时，保证最终下发的每个方案都通过物理约束校验（fail-closed）**，而不是事后才发现不可行。

---

## 2. 核心方法解读（通俗版）

想象你让一个聪明的实习生帮你安排家里一天的用电：他嘴巴很会说，方案也能列出一堆，但你不敢直接照他说的去开开关，因为他不一定真的算过功率会不会超、温度够不够。

这篇论文的招数是**"管住嘴、锁住手"**：

- **管住嘴**：让 LLM 只负责"说"——把自然语言请求翻译成结构化的调度候选（哪个设备、什么时候、怎么运行），它不负责拍板。
- **锁住手**：一个**确定性的 critic（审查员）**负责"动手"前的最后一道关。它把 LLM 生成的 day-ahead 候选方案**重新用 MIP/MILP 重建一遍**，逐项硬校验：schema 对不对、家电循环约束满不满足、设备功率超没超、热舒适区间守没守住、整条馈线功率上限爆没爆。只有全部通过，方案才会被授权执行。

关键设计是 **物理授权与语言生成彻底分离**：语言模型可以胡说，但最终下发的永远是审查员验算过的方案。这就构成了"fail-closed"（失败即拒绝）闭环，而不是常见的"先执行再后悔"。

## 3. 算法/模型框架说明

```
自然语言请求（如"明天9-18点在家，帮我省钱充电"）
        │
        ▼
  编排器 Orchestrator（Qwen 3.5 系列，多步 ReAct）
        │  拆解任务、分派
        ├──► 可平移家电 Agent
        ├──► EV 充电 Agent
        └──► 热控 Agent
        │  各自返回结构化调度候选
        ▼
  确定性 Critic（MIP/MILP 重建 + 硬约束校验）
  校验项：schema / 循环约束 / 设备功率 / 热舒适 / 馈线功率上限
        │
   通过？─否──► 拒绝并回退（fail-closed）
        │是
        ▼
   授权执行 → 独立 final replay 复核
```

几个关键实验结果：

- 单家电 MIP 调度：83.3% 的 run 可行；
- 耦合调度（多设备联合）：仅"局部反馈"时 0 个可行；改用**多步策略**后 6/6 可行（27B 3/3、35B-A3B 3/3）；
- 可行成本：27B 为 2522.499 日元、35B-A3B 为 1592.697 日元，略高于数学最优 1343.380 日元；
- 所有被接受的方案都通过独立 final replay。

---

## 4. 关键创新点

1. **授权与生成分离**：物理合法性由确定性 critic 保证，不依赖 LLM 的"自觉"，这是最核心的架构创新
2. **fail-closed 工作流**：宁可拒绝也不下发不可行方案，把安全放在首位
3. **多步策略优于局部反馈**：实证发现让 Agent 多步思考（而非一步生成+局部纠错）才能稳定产出耦合可行方案
4. **成本接近最优**：35B-A3B 与 MILP 最优解仅差 ~18.6%，说明"安全约束 + 智能体自由"可以兼顾

---

## 5. 与已有方法的区别

| 方法 | 关键区别 |
|------|----------|
| LLM 直接生成调度 | 无物理校验，经常不可行 |
| LLM + 简单提示约束 | 依赖模型自律，不可靠 |
| 纯 MILP 求解 | 最优但无法理解自然语言、缺交互性 |
| 本文（critic 重建+授权） | 用确定性求解器当"守门人"，LLM 当"翻译官" |

---

## 6. 为什么值得关注

- **可落地性强**：这是把 Agent 用于能源调度的"安全兜底"范式，几乎可以直接借鉴到 VPP/DER 聚合、家庭能源管理、楼宇微网等场景
- **成本可控**：接近最优的差距已经很小，说明智能体 + 求解器混合路线成熟
- **验证完整**：单家电、耦合、不同模型规模都做了，还给了成本-最优的对比，不是空谈框架

## 7. 待思考的问题

1. critic 只做了 day-ahead 候选的硬校验，实时阶段的扰动（光伏预测偏差、用户临时改主意）怎么纳入？
2. 馈线级约束能否进一步推广到配电网电压/潮流约束，做成"Agent + AC 潮流校验"的闭环？
3. "接近最优"的成本差距（~18%）主要来自 LLM 的调度质量还是 critic 的保守性？能否用决策聚焦学习缩小？
4. 83.3% 单家电可行率意味着仍有 ~17% 被拒——这些失败模式的共性是什么，能否用更结构化的 schema 提前规避？
